## MVP vs отложенное

**MVP (до публичного запуска)**: F1, F2, F3, F4, F5, F6, F7, F8 (+ контент F9 в объёме текущих 30 уроков, публикуемом после нативного ревью).

**Отложено**: F10 (после запуска), F11 (заморожено решением), F12 (после подтверждения retention), F13 (контентная база мала).

## Рекомендуемый порядок и логика

1. **F1 → F2 → F3** — ядро обучения: сначала контракт типов (иначе новые типы потом переписывают всё), затем структура пути, затем теория (дифференциатор).
2. **F4, F5, F6** — удержание и ценность словаря; могут идти после/параллельно с F3.
3. **F7 строго до F8** — без аналитики бета не проверит гипотезу PRD.
4. **F8** — запуск; после него F10 → F11 → F12 → F13 по решению.
5. **F9 — параллельная авторская ветка**, не блокирует код, но ограничивает ценность запуска.

## Зависимости (граф, текстом)

- F2 ← F1 не требует, но общая модель контента: удобно после F1
- F3 ← F2 (структура разделов), плюс решение по формату теории
- F8 ← F1–F7
- F10 ← F1 (контракт типов)
- F12 ← F8, F7; F13 ← F9

## Фичи, требующие отдельного PRD перед техпланом

- **F3 (Теория)** — неизвестны формат (статьи? таблицы? интерактив?), объём на A1, интеграция с уроками (теория перед уроком / отдельный раздел), автор
- **F5 (Пуш-инфраструктура)** — выбор решения для пушей, сегментация, тон коммуникации («мягкое удержание»)
- **F10 (Новые типы упражнений)** — методическая спецификация каждого типа, дизайн payload-контрактов
- **F12 (Монетизация)** — модель подписки, что входит в премиум, ads vs sub
- **F13 (Placement-тест)** — методика, структура вопросов

Остальные фичи (F1, F2, F4, F6, F7, F8, F9, F11) можно вести напрямую через технический план `/plan` — требования в PRD достаточны, узкие места вынесены в вопросы ниже.

## Открытые вопросы (из PRD, отнесены к фичам)

- Инструмент аналитики для F7 (backend-события vs Amplitude vs App Store analytics)
- Формат/автор/интеграция теории — F3
- Целевой объём и темы расширения контента — F9
- Пуш-решение и сегментация — F5
- Порядок новых типов после запуска — F10 (аудирование первым?)
- Брендинг/иконка/скриншоты — F8
- Целевые цифры метрик гипотезы могут потребовать калибровки после первой беты

## Разбиение больших фич на этапы (реализуемые и проверяемые отдельно)

- **F1**: (1а) формализовать контракт типа упражнения — валидация payload на бэке, документация; (1б) полировка `translation_choice`; (1в) полировка `fill_word`; (1г) сквозная проверка на бете
- **F2**: (2а) модель уровня/чекпоинтов + админка/CSV; (2б) карта пути на клиенте; (2в) чекпоинт-механика
- **F4**: (4а) выбор/упрощение алгоритма (SM-2-lite), миграция прогресса; (4б) приоритизация очереди карточек
- **F5**: (5а) локальные напоминания; (5б) пуш-инфраструктура; (5в) настройки частоты и тон
- **F6**: (6а) TTS в уроках; (6б) картинки к словам (пайплайн + клиенты); (6в) обогащение карточек
- **F7**: (7а) событийная модель + хранение; (7б) дашборд ключевых метрик гипотезы
- **F9**: (9а) целевой объём/темы; (9б) производство ТЗ-пакетов; (9в) нативное ревью и публикация
