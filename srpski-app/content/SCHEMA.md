# Контракт контента

Единый формат, который читают оба клиента — iOS (Swift) и Android (Kotlin). Клиенты
**не генерируют упражнения и не выбирают отвлекающие варианты**: всё это делает
пайплайн на этапе сборки. Приложение получает готовый список упражнений и только
рендерит его. Это устраняет главный источник расхождений между платформами.

## Принципы

**Латиница — источник истины.** Весь контент авторится латиницей. Кириллица
генерируется транслитерацией при сборке, вручную не пишется и в источниках не
хранится.

**Сербский, белградская норма, экавица.** `mleko`, а не `mlijeko`. `hleb`, а не
`kruh`. `nedelja`, а не `nedjelja`. Валидатор проверяет это по стоп-листу.

**Источники — CSV и JSON, руками правится только они.** Всё в `content/build/`
генерируется и в гит не попадает.

## Файлы источников

### `content/lexemes.csv`

Одна строка — одна лексема или готовая фраза.

| Колонка | Обязательна | Описание |
|---|---|---|
| `id` | да | Стабильный слаг, ASCII, уникален по всему курсу. Меняя `id`, вы обнуляете прогресс пользователей по этому слову. |
| `lesson` | да | Урок, в котором слово вводится (`1.1`). Должен существовать в `course.json`. |
| `lemma` | да | Словарная форма латиницей. |
| `translation_ru` | да | Основной перевод. Дополнительные принимаемые варианты — через `;`. |
| `pos` | да | `noun` `verb` `adj` `adv` `pron` `prep` `conj` `particle` `interj` `phrase` `name` |
| `gender` | для `noun` | `m` `f` `n` |
| `aspect` | для `verb` | `impf` `pf` |
| `forms` | нет | Дополнительные словоформы через `;`. Нужны, чтобы токены предложений сопоставлялись с лексемой: `biti` → `sam;si;je;nisam`. |
| `notes` | нет | Заметка для авторов контента, в приложение не попадает. |

### `content/sentences.csv`

| Колонка | Обязательна | Описание |
|---|---|---|
| `id` | да | Уникальный слаг вида `s1_1_01`. |
| `lesson` | да | Урок, к которому относится предложение. |
| `text` | да | Предложение латиницей, с пунктуацией. |
| `translation_ru` | да | Перевод. Варианты через `;`. |
| `notes` | нет | Заметка для авторов. |

Порядок строк значим: первые предложения урока попадают в упражнения на сборку
из банка слов, следующие — в аудирование.

### `content/course.json`

Иерархия `course → sections → units → lessons` плюс грамматические заметки на
уровне урока. Здесь только структура и тексты заметок; слова и предложения
привязываются к урокам из своих CSV.

## Формат сборки

`content/build/course-ru-sr.json` — единственный файл, который забирают клиенты.

```
{
  "formatVersion": 1,
  "contentVersion": "<хеш источников>",
  "from": "ru", "to": "sr",
  "lexemes":   [ { id, lemma, lemmaCyrillic, translations[], pos, gender, aspect, audio } ],
  "sentences": [ { id, text, textCyrillic, translations[], tokens[], audio } ],
  "sections":  [ { id, title, units: [ { id, title, grammarNote, lessons: [ { id, title, exercises[] } ] } ] } ]
}
```

`tokens` — разбор предложения на слова со ссылкой на лексему (`lexemeId` может
быть `null` для служебных слов вне словаря). Даёт подсказку при тапе на слово.

`contentVersion` — хеш источников. Клиент сравнивает его со своим и понимает,
нужно ли перестраивать локальный кеш.

## Типы упражнений

Все упражнения приходят с уже готовыми вариантами ответа. Порядок вариантов
детерминирован: он вычисляется из `id` упражнения, поэтому одинаков на обеих
платформах и не меняется между сборками.

`choose_translation` — вопрос и четыре варианта, поле `direction` указывает
`ru_sr` или `sr_ru`, `correctIndex` — верный вариант.

`word_bank` — перевод показан, ответ собирается из `bank` (правильные токены плюс
отвлекающие), `answer` — эталонная последовательность токенов.

`listen_word_bank` — то же, но исходный текст скрыт до ответа, играет `audio`.

`match_pairs` — пять пар `left` (сербское слово) и `right` (перевод), поле
`solution` задаёт соответствие индексов.

## Аудио

Формат — AAC в контейнере `.m4a`: нативно играется на обеих платформах, весит
меньше mp3 и собирается на macOS без сторонних утилит. Имена файлов выводятся из
`id`: `audio/lex/<id>.m4a` для слов, `audio/sent/<id>.m4a` для предложений.
Пайплайн пишет `content/build/audio_manifest.json` со списком того, что ещё не
озвучено.

В системе macOS сербского голоса нет — доступен только хорватский `hr_HR`.
`tools/make_dev_audio.sh` использует его, чтобы разработчики не ждали студию, но
**в релиз такое аудио не идёт**: интонация и часть фонем не сербские. Продакшн-озвучка
делается носителем или внешним TTS и кладётся в `content/audio/`.
